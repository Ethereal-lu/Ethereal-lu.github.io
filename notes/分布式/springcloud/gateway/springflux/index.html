1 概述#

SpringFlux 基于 Reactor，默认使用容器是 Netty，是一种异步非阻塞IO模型，通过少量的容器线程就可以支撑大量的并发访问，所以 SpringFlux 可以有效提升系统的吞吐量和伸缩性，特别是在一些 IO 密集型应用中，例如微服务网关 Spring Cloud Gateway 就使用了 Flux，这样可以有效提升网管对下游服务的吞吐量。如果运用在日志监控系统，前端页面将不再需要通过“命令式”的轮询的方式不断向服务器请求数据然后进行更新，而是在建立好通道之后，数据流从系统源源不断流向页面，从而展现实时的指标变化曲线。

2 执行流程#

Netty服务器启动后会监听客户端的请求，当boss IO线程接收到完成TCP三次握手的请求后，会把连接套接字通道传递给worker IO线程进行具体处理，后者则会调用适配器ReactorHttpHandlerAdapter的apply方法进行处理，然后适配器就会把请求再转发给基础层的HttpHandler的实现类HttpWebHandlerAdapter的handle方法进行处理，其内部则会调用请求分配器DispatcherHandler的handle方法把请求分配到具体的controller进行执行。

SpringWebflux 核心控制器 DispatchHandler，实现了接口 WebHandler。WebHandler的源码如下：

public interface WebHandler {

    /**
     * Handle the web server exchange.
     * @param exchange the current server exchange
     * @return {@code Mono<Void>} to indicate when request handling is complete
     */
    Mono<Void> handle(ServerWebExchange exchange);

}

DispatchHandler实现了handle方法，如下：

public Mono<Void> handle(ServerWebExchange exchange) {
    return this.handlerMappings == null ? this.createNotFoundError() : Flux.fromIterable(this.handlerMappings).concatMap((mapping) -> {
        return mapping.getHandler(exchange);
    }).next().switchIfEmpty(this.createNotFoundError()).flatMap((handler) -> {
        return this.invokeHandler(exchange, handler);
    }).flatMap((result) -> {
        return this.handleResult(exchange, result);
    });
}

其中，参数ServerWebExchange是放http请求和响应信息；getHandler根据请求地址获取对应的mapping；invokeHandler调用具体的业务方法；handleResult处理结果返回。

SpringWebflux 里面 的DispatcherHandler，有3个很重要的属性，如下：

public class DispatcherHandler implements WebHandler, ApplicationContextAware {
    @Nullable
    private List<HandlerMapping> handlerMappings;
    @Nullable
    private List<HandlerAdapter> handlerAdapters;
    @Nullable
    private List<HandlerResultHandler> resultHandlers;
}
Bean typeExplanation
HandlerMapping将请求映射到处理程序。HandlerMapping的主要实现是RequestMappingHandlerMapping（用于@RequestMapping注释方法），RouterFunctionMapping（用于功能性端点路由），SimpleUrlHandlerMapping（用于显式注册URI路径模式和WebHandler实例）。
HandlerAdapter真正负责请求处理
HandlerResultHandler响应结果处理。

3 Mono和Flux#

在 SpringFlux 中Mono和Flux均能充当响应式编程中发布者的角色：

  • Mono：表示单个结果的发布者，返回0或1个元素，即单个对象，类似Java 8的Optional，但具有额外的异步能力。Mono仅发出一个元素或表示完成状态，适用于一次性结果处理，如数据库查询或远程调用。

A Mono<T> is a specialized Publisher<T> that emits at most one item via the onNext signal then terminates with an onComplete signal (successful Mono, with or without value), or only emits a single onError signal (failed Mono).

Most Mono implementations are expected to immediately call onComplete on their Subscriber after having called onNext. Mono.never() is an outlier: it doesn’t emit any signal, which is not technically forbidden although not terribly useful outside of tests. On the other hand, a combination of onNext and onError is explicitly forbidden.

Mono offers only a subset of the operators that are available for a Flux, and some operators (notably those that combine the Mono with another Publisher) switch to a Flux. For example, Mono#concatWith(Publisher) returns a Flux while Mono#then(Mono) returns another Mono.

Note that you can use a Mono to represent no-value asynchronous processes that only have the concept of completion (similar to a Runnable). To create one, you can use an empty Mono<Void>.

  • Flux：表示多个结果的发布者，返回N个元素，即List列表对象，类似Java 8的Stream，但具有非阻塞与异步特性。适用于多值流操作，如消息队列获取或文件逐行读取。

A Flux<T> is a standard Publisher<T> that represents an asynchronous sequence of 0 to N emitted items, optionally terminated by either a completion signal or an error. As in the Reactive Streams spec, these three types of signal translate to calls to a downstream Subscriber’s onNext, onComplete, and onError methods.

With this large scope of possible signals, Flux is the general-purpose reactive type. Note that all events, even terminating ones, are optional: no onNext event but an onComplete event represents an empty finite sequence, but remove the onComplete and you have an infinite empty sequence (not particularly useful, except for tests around cancellation). Similarly, infinite sequences are not necessarily empty. For example, Flux.interval(Duration) produces a Flux<Long> that is infinite and emits regular ticks from a clock.

3.1 Mono常用API#

  • Mono.just() 类似于 List.of() ，用于构建 Mono 对象
Mono<LocalDateTime> just = Mono.just(LocalDateTime.now());
just.subscribe(System.out::println);

​ just 是单例的，消费多少次都一样，每次执行just.subscribe(System.out::println)的结果都一样

  • Mono.defer() 参数为一个 Mono 对象
Mono<LocalDateTime> defer = Mono.defer(() -> Mono.just(LocalDateTime.now()));
defer.subscribe(System.out::println);

​ defer 不是单例，每次消费都会创建新的Mono对象，每次执行just.subscribe(System.out::println)的结果都是当前最新时间

  • Mono.empty() 创建一个不含任何元素的Mono，只发布结束消息
Mono.empty().subscribe(System.out::println)

​ subscribe(Consumer<? super T> consumer)让 consumer 消费 Mono 中的所有元素

  • doFirst() 在订阅Mono之前触发的行为

  • doOnError() 在消费发生异常时执行的逻辑

3.2 Flux常用API#

  • Flux.just()
Flux<Integer> just = Flux.just(1, 2, 3);
  • Flux.range()
Flux<Integer> range = Flux.range(1, 5);
  • Flux.defer()
Flux<Integer> defer = Flux.defer(() -> Flux.just(1, 2, 3));
  • switchIfEmpty(Publisher<? extends T> alternate)将空Flux替换为alternate
  • doOnEach(Consumer<? super Signal<T>> signalConsumer) 订阅者每消费一个元素，signalConsumer也消费一次
Flux.empty().switchIfEmpty(Flux.error(new RuntimeException("error"))).doOnEach(System.out::println).subscribe();

上述示例方法都用于创建 Flux 序列，创建出来的 Flux 序列在发布这些元素之后会自动结束。fromArray()，fromIterable()和 fromStream()可以从一个数组、Iterable 对象或 Stream 对象中创建 Flux 对象。empty() 创建一个不包含任何元素，只发布结束消息的序列,在响应式编程中，流的传递是基于元素的，empty 表示没有任何元素，所以不会进行后续传递，需要用switchIfEmpty将其替换为另一个序列。never() 创建一个不包含任何消息通知的序列。

4 RouterFunction 和 HandlerFunction#

Spring框架提供了两种http端点暴露方式来隐藏servlet和reactor原理，一种是基于注解的形式@Controller或@RestController以及其他的注解如@RequestMapping、@GetMapping等等。另外一种是基于路由配置RouterFunction和HandlerFunction的，称为“函数式WEB”。

WebFlux推荐使用RouterFunction

下方示例中，PersonRouteFunction将路由映射到PersonHandlerFunction的具体方法

@Configuration
public class PersonRouteFunction {
    @Bean
    public PersonHandlerFunction handler() {
        return new PersonHandlerFunction();
    }
    @Bean
    public RouterFunction<ServerResponse> routerFunction(final PersonHandlerFunction handler) {
        return RouterFunctions.route()    // 可以添加类似 @RequestMapping 的公共前缀路由
                .GET("/getPerson", RequestPredicates.accept(MediaType.APPLICATION_JSON), handler::getPerson)
                .GET("/getPersonList",RequestPredicates.accept(MediaType.APPLICATION_JSON), handler::getPersonList)
                .build();
    }
}

public class PersonHandlerFunction {
    // 1.0创建线程池
    private static final ThreadPoolExecutor bizPoolExecutor = new ThreadPoolExecutor(8, 8, 1, TimeUnit.MINUTES,
            new LinkedBlockingQueue<>(10));

    Mono<ServerResponse> getPersonList(ServerRequest request) {
        // 1.根据request查找person列表
        Flux<String> personList = Flux.just("abc", "def", "xyz")
                .publishOn(Schedulers.fromExecutor(bizPoolExecutor))// 1.1 切换到异步线程执行
                .map(e -> {// 1.2打印调用线程
                    System.out.println(Thread.currentThread().getName());
                    return e;
                });

        // 2.返回查找结果
        return ServerResponse.ok().contentType(MediaType.APPLICATION_JSON).body(personList, String.class);
    }

    Mono<ServerResponse> getPerson(ServerRequest request) {
        // 1.根据request查找person,
        Mono<String> person = Mono.just("abc");
        // 2.返回查找结果
        return ServerResponse.ok().contentType(MediaType.APPLICATION_JSON).body(person, String.class);
    }
}
